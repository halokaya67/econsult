The eleven review rounds

Every artifact was reviewed by a separate checker before it could be used, and the finished change was reviewed again at the end. Each round read the artifact against the brief, the repository and the language canon, and reported what it could prove.

← Back to the record

How to read a verdict

  • FAIL — the round found at least one blocker: something that would not work as written. A blocker had to be fixed in the artifact before the gate, and the fix was re-reviewed in the next round.
  • PASS_WITH_FLAGS — no blocker. The warnings and information items were recorded, and each was either fixed or answered with a stated decision.

The counts below are the round's own numbered findings: blockers (C), warnings (W) and information items (I). Later rounds restate items that are still open, so the same finding can appear in more than one round.

What the rounds changed

The plan never passed a checker on its first shape: three rounds removed twelve blockers before execution started, and several of them — test files that would have been loaded as routes, a provider nesting mistake, a schema helper inferring the input type instead of the output type — would have cost more to discover during implementation than they cost to fix on paper.

On the spec side the rounds mostly replaced plausible claims with verified ones. One platform decision kept its conclusion while its stated reason was rewritten, because a checker read the installed library code and found the original rationale untrue for this runtime — and the round after that found one clause of the replacement wrong in turn.
