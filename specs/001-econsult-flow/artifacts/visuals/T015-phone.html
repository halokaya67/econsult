Defects

recipient-placeholder-largest.png, recipient-placeholder-default.pngNo back affordance on the first step of the e-consult flow. recipient is the root screen of the nested econsult stack, so that stack renders no back button, and the root stack hides its own header for the group — leaving a header with a title and nothing else. Verified three ways: the accessibility tree’s navigation bar contains only the title label and no button node; a search for role=button matched no element on the screen; and the driver’s back command returned “in-app back control is not available”. The iOS edge-swipe gesture does still return to home (verified), so the user is not trapped, but that gesture is invisible to VoiceOver and unavailable to Switch Control, and it is the only way out.

Notes (not defects)

  • The blue gear at the top left of every screenshot is Expo Go’s own floating developer-menu button, not app UI. It overlaps the left end of the navigation bar in all captures; the back-affordance finding above was confirmed from the accessibility tree rather than from pixels, so the overlay does not affect it.
  • “Developer settings” appearing above the primary button is intentional: the shared screen scaffold renders its action as the last child of the scroll view so the keyboard can never cover it. Recorded as an observation, not a defect.
