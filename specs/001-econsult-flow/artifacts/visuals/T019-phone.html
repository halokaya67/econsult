Defect flags

Blocking · declared criterion not met

A failed retry reports nothing new

Tapping Try again shows its busy state for the length of the upload and then returns to “Try again” with the alert unchanged. The patient waits, sees the spinner finish, and gets no word on whether anything happened.

Mechanism, observed not fixed: retryAttachment calls uploadOrFail (src/features/econsult/submit.ts), which catches every isApiError and returns the status "failed". The mutation therefore resolves, so retry.error in PhotoOutcome (src/app/econsult/sent.tsx) stays null, the sendErrorCopy line never renders, and the catch that would announce() it is unreachable for API failures.

// src/features/econsult/submit.ts
async function uploadOrFail(...): Promise<AttachmentStatus> {
  try { await services.uploadAttachment(econsultId, photo); return "attached"; }
  catch (error) {
    if (!isApiError(error)) throw error;   // only a non-API bug ever rejects
    return "failed";                        // server / network / timeout all land here
  }
}

Evidence: retry-failed-default.png, a11y-retry-failed-default.txt. Reproduced twice, with the busy state confirmed by polling in between.

Minor · cosmetic, outside the declared checks

The AX3XL heading breaks mid-word

“Message sent” renders as “Messa / ge sent” at the largest text size: the screen-heading font scale is uncapped, so the first word is wider than the 370 pt text column. Nothing is clipped and the step’s criterion still holds. T018 recorded the uncapped heading as known and accepted; this is the same token, with a mid-word break as new visible evidence.

Unverifiable on this device

The device snapshots expose frames, labels, roles and values, but no traits, no screen-reader focus and no announcement channel. So three things in the step’s contract were checked in the source and not on the device: that focus lands on the header (focusForScreenReader in a mount effect), that the alert carries accessibilityRole="alert", and what VoiceOver actually speaks. The grouping is visible indirectly — the alert’s two children fold into one accessible node whose label is the alert text.
