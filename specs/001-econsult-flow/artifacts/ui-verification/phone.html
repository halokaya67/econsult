Verdict

All ten scenarios PASS. On the first run eight passed outright and scenario 7 failed (fixed and re-driven to PASS); the Accessibility Inspector audit passed on all five audited states. No crashes, no LogBox, no bundler warnings beyond the cache notice.

Scenarios

1. Happy path with photo (prc-0421) — PASS

  1. Home → "Write to your practice" → step 1, "STEP 1 OF 3", three recipients (Dr. J. de Vries GP / M. Bakker Practice nurse / S. Jansen Practice assistant).
  2. Continue reported [disabled] before any choice.
  3. Picked Dr. J. de Vries → "radio button, checked" on it, unchecked on the other two; Continue enabled.
  4. Continue → "STEP 2 OF 3", required choice plus optional free-text field.
  5. Answered "1 to 4 weeks" → Continue → "STEP 3 OF 3", "To: Dr. J. de Vries" with Change, message field, camera-unavailable note, "Choose from library", Send.
  6. Typed "My knee has hurt for two weeks after a fall"; with the keyboard up the field stayed fully visible, notch and home indicator clear.
  7. Choose from library → the system picker opened; no Photos permission dialog on iOS 26 (the modern picker needs none).
  8. Picked the first library photo → "Your photo" preview plus "Remove photo"; "Choose from library" replaced.
  9. Send → busy state "Sending your message", Change / Remove photo / Send all [disabled], Send relabelled "Sending".
  10. Confirmation: "Message sent", "Sent to Dr. J. de Vries.", the reply-time line, "Reference: ec-1", "Your photo was attached.", Done; nav bar "Sent" with no back control.
  11. Back swipe and the driver's back action were both no-ops on the confirmation.
  12. Done → Home. Evidence: s01-01 … s01-11. Notes: after returning from the picker the message field re-takes focus, so the keyboard covers the fresh preview until the user scrolls (cosmetic).

4. Partial photo failure and retry — PASS

"Fail: Upload photo" = Server. Step 3 with a library photo, Send → intermediate "Message sent, adding your photo" → confirmation with the alert "Your message was sent, but the photo could not be attached." plus "Try again" and "Continue without the photo". Try again → busy "Attaching your photo" ([disabled], the other control stays enabled) → the alert gained "The photo still couldn't be attached. You can try again or continue without it." A second Try again left the line present exactly once. Continue without the photo → alert gone, Done remains. Fault reset. Evidence: s04-01 … s04-06.

5. Create failure — PASS

"Fail: Create message" = Network. Step 3 Send → inline card "Your message wasn't sent" / "We couldn't reach your practice. Check your connection and try again." with "Try again"; route unchanged, field still editable. Try again → the same single error. Fault reset. Evidence: s05-01 … s05-03.

6. Offline — PASS

Force offline ON → Home shows "You're offline. You can keep writing, but sending needs a connection."; step 1 loads offline-first with the banner; steps 2 and 3 show the banner; Send [disabled] on step 3 and stays disabled with text typed. Force offline OFF → banner gone, Send enabled again. Evidence: s06-01 … s06-05.

7. Discard guard via Home — FAIL on the first run, PASS on the re-drive

First run (head bfe019d): step 3 typed "draft to lose" → Change → step 1 → header "Home" → dialog "Discard your message?" / "Your message and photo will be lost." with "Keep writing" and "Discard". Keep writing kept the draft (verified by walking forward). Discard dismissed the dialog but stayed on step 1 and kept the draft; the dialog re-raised on every Home press, so the patient was trapped in the flow. Silent: no JS error. Evidence: s07-01 … s07-04. Re-drive (head 48896ef): the same path. Keep writing keeps the draft byte-identical. Discard now lands on Home ("Your practice", "Hello, Ria de Boer.", "STEP 1 OF 3" gone, dialog absent) and the next Write starts with an unselected step 1, Continue disabled and an empty message field. The back-action variant (driver back from step 1) raises the same dialog and Discard lands on Home too. Evidence: s07r-01 … s07r-05, s07r-a11y-step3-fresh.txt.
