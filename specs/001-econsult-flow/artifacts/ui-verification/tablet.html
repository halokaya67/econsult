Device: iPad Pro 11-inch (M5) simulator, Expo Go 57.0.9. Head: 48896ef. Text size: medium unless stated. Portrait unless stated.

Since then. Two readings below have been overtaken. The photo preview no longer fills the content width: it is capped at 360 points, the fix for the sliver of photo a Samsung tablet showed. And the clean iPad photo-picker result did not hold on a real iPad, where the message step blanked when the picker returned, because iOS reports the out-of-process picker's keyboard frame too; the screen scaffold now pads for the keyboard itself.

Verdict

All six scenarios PASS. No functional or visual defect. One non-failing layout observation: the form column runs 802 pt wide in an 834 pt portrait canvas (1178 pt of 1210 pt in landscape), so body copy and the full-width buttons stretch nearly edge to edge; a centred max-width column of roughly 560 to 680 pt would read better on iPad and would not change phone rendering.

Form-factor checklist (tablet)

  • Content width: OBSERVATION, not a failure. 802 pt of 834 pt in portrait (16 pt gutters), 1178 pt of 1210 pt in landscape. Body copy runs a single line nearly edge to edge and the primary buttons read as oversized; a centred max-width column would help on iPad without affecting phones.
  • Touch targets ≥ 48 pt: PASS (buttons 48 pt, recipient rows 93.5 pt, option rows 48 pt; the system nav back button is 44 × 44 pt; at the largest size buttons grow to 86–102 pt).
  • Safe-area clearance: PASS (nav bar from y 32, content from y 86, deepest content at y 1159 of 1210).
  • Developer settings as an iPad sheet with Cancel reachable: PASS, presented as a full-width top-inset sheet rather than a centred card; Cancel works and dismisses without applying.
  • Keyboard does not cover the edited field: PASS.
  • Photo picker on iPad: PASS (proper iPad sheet with sidebar; returns cleanly with the preview shown).

None. setup.log has no error, red box or exception; the only warning is the bundler's empty-cache notice. No LogBox node in any tree. Reference ids read "ec-1" on each send because each was the first send after a relaunch (per-session counter in the fake).
